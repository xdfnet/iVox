> [playback-sources.md](playback-sources.md)），不谈队列怎么实现（见

## 术语（讨论播报只用这四个词）

历史上我们就在用词上反复对不上，导致改错地方。其它说法（"assistant"、"一句"、"一段"）一律作废。

| 概念 | 是什么 | 谁划分的 | 系统里的身份 |
|---|---|---|---|
| **摞** | **一次回复**：你发一条信息 → AI 答一次 | **你按下回车**那一刀 | `turn_id` |
| **页** | 一摞里"说了一段"的一次 | 一条 assistant 消息（Claude 的 `message_id`、codex 的 `item_id`、pi 的翻页信号） | 页号 |
| **块** | 1～80 字的**合成单位**（**服务拿去播报用的，不是给用户看的**）：页上的文字被切开、送去合成的最小粒度 | iVox 自己切（`cleanText → splitSentences`） | `PlaybackJob` |
| **桶** | 队列里的**排队单位**，一摞 = 一桶 | PlaybackQueue | 队列元素 |

```
一摞（= 一桶）        一次回复
 ├─ 页               一条 assistant 消息
 │   ├─ 块           内部撕下来合成播放的一条
 │   └─ 块
 └─ 页
```

**读法**：捏着队首那一摞 → 翻到当前页 → **撕下一个块**去合成播放 → 这页撕完翻下一页 → 换下一摞。

## 场景清单

> 这是**唯一可信的场景基准**：设计对着它写、回归对着它验。改队列语义前先改这里。

| # | 场景 | 期望行为 |
|---|---|---|
| 1 | **同一页分多次到**：页先占位、正文陆续进（Claude 按行批、pi 按 delta） | 追加进同一页，不得当成新页 |
| 2 | **迟到的旧帧**：摞被跳掉/掀桌后增量帧仍在来 | 静默丢弃，绝不重新开口 |
| 3 | **块播完了、字还没来**（摞仍在说话） | 字幕不收，挂起等下一批；新内容来了揭掉宽限的印 |
| 4 | **收尾信号丢了**：工具的 Stop 钩子没来 | 「队列见底 + 设备把音频播完 + 再静候一段」兜底判定说完 |
| 5 | **跳页**（Ctrl+2） | 掐在播 + 丢掉当前页剩余块 + 接着下一页；无页来源只掐在播 |
| 6 | **跳摞**（Ctrl+1） | 掐在播 + 丢整摞 + 拦它的后续增量 |
| 7 | **掀桌**（Ctrl+Esc / 右⌘） | 全场清 + 所有轮作废 |
| 8 | **两会话并行**：两个工具同时排队 | 互不误杀；先来的播完才轮到后一个 |
| 9 | **多来源混排**：流式 + 整段同时来 | 按到达序稳定排队，谁都不插队（只有 Cmd+D 译文例外） |
| 10 | **插队例外**：Cmd+D 译文 | 插队首、念完原顺序恢复；**不掀桌**，其余内容一个不丢 |
| 11 | **轮被自取消**（pi 一条消息开双流、其中一条刚开就被 `{cancel}`） | 丢弃该轮并把身份交还给它顶掉的那一轮，否则承载正文的轮被判成过期旧轮、整轮哑掉 |
| 12 | **自然播完与新内容撞在同一瞬间**：管道刚退出、新帧就入队 | 怎么撞都得收敛——有活就补起播放，没活就收字幕，不许留下「有活没人干」的挂起 |
| 13 | **合成失败**（模型报错） | 丢掉这一块继续往下，不能卡在同一个块上死循环 |
| 14 | **daemon 退出**（SIGINT / SIGTERM） | 清场收尾；与用户打断是两条路径，别混用 |

## 顺序语义（不可协商的底线）

**长期顺序只由到达顺序决定，谁都不永久插队。** 机器最多「借道」——只有 Cmd+D 译文是插队，
念完即走。打断权**只归用户快捷键**，工具的新一轮、新的收尾信号都不得打断在播的。

由此推出一条容易被误当成 bug 的行为：**队首那摞挂着等字时，后到的摅不能插到它前面**
（场景 8/9 一起保证）。看到「空着却不播」不是卡住，是规矩。

## 打断粒度

打断按「层」走，一层一键：

| 键 | 单位 | 干什么 |
|---|---|---|
| **Ctrl+2** | **页** | 这一页剩下的不念了，翻下一页 |
| **Ctrl+1** | **摞** | 整摞不要了；它后面还没到的页也不会再开口 |
| **Ctrl+Esc** | 全部 | 掀桌（打断全场；背景音乐不归它管） |

身份弱的一方自动退化：没有页的来源，Ctrl+2 退化成「只掐在播」；既无页又无摞的来源，
Ctrl+1 退化成「丢掉当前那一桶」。

## 解耦约束（架构上必须守住的三条）

### 一、队列不认「摞」，只放有序的块

播放、背压、打断是**通用能力**；摞/页/身份/收尾是**接入层的事**。队列一旦塞进
Claude 专属的页概念和宽度手感，就再也干净地复用不了——今天那个「陈旧页号」bug
（跳页后忘了清靶心，导致第二下按压误删后到的内容）就是概念混住的下场。

> 身份管理归接入层；队列只负责「把这些块按顺序念出来，念得连续、可被三层打断」。

### 二、接入适配只在一处

「一个 AI 工具的输出 → 摞/页/块」这段逻辑，**只能在接入层的一处实现**。
hook.sh、pi 扩展、任何未来的适配器都只做**转发**，不做判断、不自己拼协议字段。
理由很实际：这段逻辑现在散在 shell+python、TS、Swift 三处，改一次协议要动三个语言的文件。

### 三、协议要能演进

socket 帧带版本号，未知字段忽略。hook.sh 与 pi 扩展是**独立发布**的，协议一改它们未必
跟着升级——没有版本号，改协议就是一次静默的破坏。

### 四、帧格式要有跨语言的契约测试

iVoxKit 已有 StreamFrame 测试，但**只测 Swift 自己**。pi 的 TS 实现与 Swift 的解析如果
对不上，两边测试都绿、实际跑不通——这正是「悄悄腐烂成假绿」的路子。跨语言的那一半
必须有对应测试。
