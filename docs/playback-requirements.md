# 播报需求层（第二层）

> 这一层回答：**播报必须满足什么。** 不谈谁在说话（见
> [playback-sources.md](playback-sources.md)），不谈队列怎么实现（见
> [playback-queue.md](playback-queue.md)）。
>
> 本文与代码不符时以代码为准，但请先想清楚：是代码错了，还是需求变了。

## 本文的编写准则：目的优先

**动作是有目的的，方案是为目的服务的。**

所以本文每条定义都要能回答一句：**它服务于哪个用户目的？** 服务不了的结构不进术语——
不管它在代码里多自然、让实现多省事。用户不为实现元素操作，就别让它进用户认知。

这就是本文「严谨」的判据：一句话若只说得清「代码里是什么」而说不清「为了什么」，
它就是歧义的温床。

配套一条：**全文只用「掐」和「掀」两个动作词。** 「撕」「翻」「读」「跳」「丢弃」「清场」
等一律不用——同一套动作里混比喻和实词就是歧义的温床（比如「翻」到底是掀页还是换页）。
方法名与历史表述除外，它们是代码里的既有事实。

## 术语（讨论播报只用这三个词）

历史上我们就在用词上反复对不上，导致改错地方。其它说法（"assistant"、"一句"、"一段"、"桶"）一律作废。

| 概念 | 是什么 | 谁划分的 | 系统里的身份 | 服务于什么目的 |
|---|---|---|---|---|
| **摞** | **你给 AI 工具发一条信息之后，它为此产生的全部回复**。中间可能夹工具调用、AI 来回答很多次——那些回复全都算这一摞 | **你按下回车**那一刀 | `turn_id` | Ctrl+1「这次提问的回答我不要了」 |
| **页** | 一摞里的**一次回复**，即**一条 assistant 消息**——**这条消息里同时带工具调用也算一页**，不切 | Claude 的 `message_id`、codex 的 `item_id`、pi 的翻页信号 | 页号 | Ctrl+2「这一段我不想听了」 |
| **块** | 页上的文字被切成的**最小合成单位**（**服务拿去播报用的，不是给用户看到的**）。切多大是个**实现取舍**：小了打断粒度碎、合开销大；大了单块耗时长、首声延迟高。用户听不出块边界，故不给它按键 | iVox 自己切（`cleanText → splitSentences`，现取 ≤80 字） | `PlaybackJob` | 让「掐在播」能在可接受的粒度上生效 |

**「桶」不是术语**，它是队列的排队单位、一个纯实现元素（见 [playback-queue.md](playback-queue.md)）。
用户从不按桶操作——按键只为按页、摞、全部这三种**语义单位**丢弃。把桶与摞并列成术语，等于拿
实现语言描述语义，「一摞 = 一桶」那句自相矛盾正是这么来的（已于 2026-10-17 移除）。

```
一摞     你发一条信息，AI 为此产生的全部回复
 ├─ 页   第一次回复（还没调工具，先答了）
 │   ├─ 块  页上切下送去合成的一条
 │   └─ 块
 ├─ 页   调完工具之后的回复
 └─ 页   ……
```

实测一个 turn 底下最多见过 19 页（`hook.log` 统计）。**「摞」是一叠纸，不是其中一张**——
早期文档写成「摞 = 一次回复」是自相矛盾（一次回复怎么会是一摞），已于 2026-10-17 更正。

**顺序**（只有两个动作：掐 = 断在播，掀 = 丢弃某一层）：从队列头取一摞 → 取它当前的页 →
取当前块去合成播放 → 块取完取下一页 → 页取完取下一摞。**中途用户随时可以掐某一层或掀某一层。**

## 三个已定的结构决定（2026-10-17，按目的推出）

都是从「服务于什么目的」反推的，不是从「结构怎么自洽」推的：

**一、桶不进术语**（见上）。用户只为页、摞、全部三种语义单位操作，桶是实现元素。

**二、页是固定的一层，无页来源退化成匿名页。**
*目的*：让 Ctrl+2 在**任何来源下行为一致**——按下去永远是「掀掉我刚听到的那一页」，
用户不必先想「这个工具有没有页」。挂匿名页则退化分支一个都不用写；不挂则每个来源
各长一支，文档和代码都要跟着长。所以页不是「可选的一层」，是**永远存在、无页时页号为空**。

**三、形态 C（hook 终了一次，如 codex 现状）语义上是一摞一页。**
*目的*：用户不该因为接的工具不同而失去同一个按键。按语义判——一次 Stop 就是
一次输入的一次回复，即一摞一页。接法改掉（换成订阅事件流）后它会变成真正的多页。

## 场景清单

> 这是**唯一可信的场景基准**：设计对着它写、回归对着它验。改队列语义前先改这里。

| # | 场景 | 期望行为 |
|---|---|---|
| 1 | **同一页分多次到**：页先占位、正文陆续进（Claude 按行批、pi 按 delta） | 追加进同一页，不得当成新页 |
| 2 | **迟到的旧帧**：摞被掀后它的增量帧仍在来 | 静默丢弃，绝不重新开口 |
| 3 | **块播完了、字还没来**（摞仍在说话） | 字幕不收，挂起等下一批；新内容来了揭掉宽限的印 |
| 4 | **收尾信号丢了**：工具的 Stop 钩子没来 | 「队列见底 + 设备把音频播完 + 再静候一段」兜底判定说完 |
| 5 | **掀页**（Ctrl+2） | 掐在播 + 掀当前页的全部块（还没来的页不拦——见「能力边界」）。**所有来源行为一致**：无页来源掀的就是那个无页号的页 |
| 6 | **掀摞**（Ctrl+1） | 掐在播 + 掀整摞 + 立墓碑拦它后续的增量（**彻底的**） |
| 7 | **全掀**（Ctrl+Esc / 右⌘） | 掐在播 + 掀光所有摞 + 所有轮作废 |
| 8 | **两会话并行**：两个工具同时排队 | 互不误杀；先来的播完才轮到后一个 |
| 9 | **多来源混排**：流式 + 整段同时来 | 按到达序稳定排队，谁都不插队（只有 Cmd+D 译文例外） |
| 10 | **插队例外**：Cmd+D 译文 | 插队首、念完原顺序恢复；**不全掀**，其余内容一个不丢 |
| 11 | **轮被自取消**（pi 一条消息开双流、其中一条刚开就被 `{cancel}`） | 丢弃该轮并把身份交还给它顶掉的那一轮，否则承载正文的轮被判成过期旧轮、整轮哑掉 |
| 12 | **自然播完与新内容撞在同一瞬间**：管道刚退出、新帧就入队 | 怎么撞都得收敛——有活就补起播放，没活就收字幕，不许留下「有活没人干」的挂起 |
| 13 | **合成失败**（模型报错） | 丢掉这一块继续往下，不能卡在同一个块上死循环 |
| 14 | **daemon 退出**（SIGINT / SIGTERM） | 清场收尾；与用户打断是两条路径，别混用 |

## 顺序语义（不可协商的底线）

**长期顺序只由到达顺序决定，谁都不永久插队。** 机器最多「借道」——只有 Cmd+D 译文是插队，
念完即走。打断权**只归用户快捷键**，工具的新一轮、新的收尾信号都不得打断在播的。

由此推出一条容易被误当成 bug 的行为：**队首那摞挂着等字时，后到的摅不能插到它前面**
（场景 8/9 一起保证）。看到「空着却不播」不是卡住，是规矩。

## 打断粒度：三档都是「掐 + 掀」

**掐** = 掐断正在播的那一块；**掀** = 把某一层的全部内容丢掉。
三档只有「掀」的层不同，掐的部分完全一样：

| 键 | 动作 | 掀的范围 |
|---|---|---|
| **Ctrl+2** | 掐在播 + **掀当前页** | 这一页的**全部块**（含还没轮到播的），后面的页照播 |
| **Ctrl+1** | 掐在播 + **掀当前摞** | 这一摞的全部页——**含还没到的**（立墓碑拦它的后续增量） |
| **Ctrl+Esc** | 掐在播 + **全掀** | 所有摞、所有页（背景音乐不归它管） |

### 能力边界：掀页掀不彻底，掀摞才彻底

- **掀摞是彻底的**：摞号从第一页起就有，立个墓碑，这一摞后续送来的增量全拦得住。
- **掀页只能掀「已经出现的那一页」**：Claude 的页号是**每批随增量送来的**（`message_id`），
  pi 是**翻页帧才发号**——你按下 Ctrl+2 时，这一摞后面还会不会再冒新页、页号是什么，
  服务端**无从得知**。所以还没来的页，等它来了照样播。

  要让「掀页」也彻底，得让接入方**预先分配页号**（例如这一摞开始时就声明「最多 N 页」），
  那是协议变更，不在当前范围内。

### 身份弱的一方自动退化

无摞来源没有「这次提问的回答」这个语义单位，Ctrl+1 掀掉的是
队列里当前这一段待播内容——**它是实现层的说法，不是术语**（见「三个已定的结构决定」第一条）。

| 来源身份 | Ctrl+2 | Ctrl+1 | Ctrl+Esc |
|---|---|---|---|
| 有摞有页 | 掐 + 掀当前页 | 掐 + 掀当前摞 | 掐 + 全掀 |
| 有摞、无页（整段一次） | 掐 + 掀当前页（无页号） | 掐 + 掀当前摞 | 掐 + 全掀 |
| 无摞无页（手动 · Cmd+D） | 掐 + 掀当前页（无页号） | 掐 + 掀当前那一段待播内容 | 掐 + 全掀 |

## 解耦约束（架构上必须守住的四条）

### 一、队列不认「摞」，只放有序的块

播放、背压、打断是**通用能力**；摞/页/身份/收尾是**接入层的事**。队列一旦塞进
Claude 专属的页概念和宽度手感，就再也干净地复用不了——今天那个「陈旧页号」bug
（掀页后忘了清靶心，导致第二下按压误删后到的内容）就是概念混住的下场。

> 身份管理归接入层；队列只负责「把这些块按顺序念出来，念得连续、可被三层打断」。

### 二、接入适配只在一处

「一个 AI 工具的输出 → 摞/页/块」这段逻辑，**只能在接入层的一处实现**。
hook.sh、pi 扩展、任何未来的适配器都只做**转发**，不做判断、不自己拼协议字段。
理由很实际：这段逻辑现在散在 shell+python、TS、Swift 三处，改一次协议要动三个语言的文件。

### 三、协议要能演进

socket 帧带版本号，未知字段忽略。hook.sh 与 pi 扩展是**独立发布**的，协议一改它们未必
跟着升级——没有版本号，改协议就是一次静默的破坏。

### 四、帧格式要有跨语言的契约测试

iVoxKit 已有 StreamFrame 测试，但**只测 Swift 自己**。pi 的 TS 实现与 Swift 的解析如果
对不上，两边测试都绿、实际跑不通——这正是「悄悄腐烂成假绿」的路子。跨语言的那一半
必须有对应测试。
