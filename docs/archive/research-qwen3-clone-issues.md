# Qwen3-TTS 克隆相关问题与社区经验

**整理日期**：2026-10-05
**来源**：[Qwen3-TTS Issues](https://github.com/QwenLM/Qwen3-TTS/issues) / [Pull Requests](https://github.com/QwenLM/Qwen3-TTS/pulls)
**用途**：汇总 Base 模型声音克隆（Voice Clone）的已知坑与规避经验，供排查参考。

## 一、克隆的两种模式（PR #101）

| 模式 | 输入 | 特点 |
|---|---|---|
| **ICL 模式** | 参考音频 + refText | 音色还原度高（iVox 现用） |
| **X-Vector Only** | 仅参考音频，无需 refText | 只提说话人 embedding，省事但相似度低 |

## 二、流式克隆"越说越快"（最需警惕）

来源：PR #362、issue #239 / #290。

**机制**：流式模式按 12.5 token/s 喂文本，远快于说话消耗（约 4–5 token/s）。随生成进行，文本积压增大、隐式限速消失，语速向模型的"快语速先验"漂移。长参考音频会在 prefill 阶段提前喂入大量目标文本，使限速从一开始就不存在。

**实测**（1.7B-Base, MPS, 固定种子, 同参数）：

| 配置 | 同一段内语速漂移 |
|---|---|
| 流式 + 12.9s 参考 | **+16.7%** |
| 流式 + 4s 参考切片 | −2.3% |
| 非流式 + 12.9s 参考 | **0.0%** |

且流式模式下，无论参考音频本身语速多慢（112–182 wpm），输出都收敛到约 195 wpm。

**结论 / 规避**：
- 克隆**默认走非流式**（`non_streaming_mode=True`），语速稳定。
- 若必须用流式，**参考音频控制在约 5 秒以内**。
- 当前权重下，推理层无法修复（社区试过多种喂法均导致立即 EOS 或失控），需训练侧解决。

> ⚠️ 与 iVox 相关：现采用流式 + 克隆，需留意参考音频时长与语速漂移。

## 三、开头 / 短文本不稳定

| Issue | 现象 | 规避 |
|---|---|---|
| #341 | 开头 1–2 秒复述参考音频末尾的词，再进入正文 | 有人剪掉参考音频末尾短语后解决 |
| #200 / #119 / #16 | 开头多个"的"、杂音、多余笑声 | — |
| #343 | 短文本 / 开头 1–2 秒音色不稳，偶发性别翻转、变声，长文本才稳定（约 15% 短句） | 同文本放入更长句子中则正常 |

## 四、其他共性问题

- **#68**：短文本可能无限延长，需手动设 `max_new_tokens`；多人对话中英混出。
- **#68 / #277 / #256 / #151**：数字、中英混杂读错（英文句中数字按中文读、时间串读错）。
- **#134**：跨语言克隆会保留参考音频原口音。
- **#61 / #80**：多人对话中突然变成另一个说话人。
