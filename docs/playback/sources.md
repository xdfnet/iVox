# 播报接入方层

> 这一层只回答一个问题：**谁在往播报队列里说话，它们各自拿得出什么。**
> 播报侧必须处理对的场景见 [需求层](requirements.md)；
> 队列怎么存、容器怎么设计**本文不谈**。
>
> 读法顺序：**目的层 → 接入方层（本文）→ 需求层 → 实现层**。有分歧先翻 [目的层](purpose.md)。
> 本文与代码不符时以代码为准，但请顺手改本文——这张表是后两层的基准。

## 共性：不管接法多不一样，塌缩后是同一种东西

术语以 [需求层](requirements.md) 为准，本文只说**各接入方送来的字段分别能决定什么**：
摞号与页号**一律由助理自编**（`PlaybackSegment.localID` / `PlaybackPage.localID`），
接入方给的 `turn_id` / `message_id` / 翻页信号**只决定「这些块算不算同一摞、同一页」，
不决定它们是谁**。块 = 服务自己切的合成单位（`PlaybackBlock.seq`，全局单调）。
**一条 assistant 消息里同时带工具调用也算一页**，不切——那一页是什么由接入方说，
它自己的编号只是备注。

进队列前，所有接入方都被压成同一种形状：

```
一摞（turn）  +  一页（page）  +  页内的增量正文  +  「说完了」信号
```

**流式是常态，不是特例**：页先占位、正文陆续往里塞，这就是「纯流式」。两个接入方现在都是这样。

## 对齐表（目标态）

| | 摞（turn） | 页（page） | 页内增量 | 现状 |
|---|---|---|---|---|
| **Claude Code** | 每批的 `turn_id`；缺失时回落 `message_id` | 每批的 `message_id` | MessageDisplay 分批带 | ✅ 已是流式 |
| **pi** | 连接首帧自带的 turn 号（扩展自编，只作线索） | `{page}` 帧（页号由助理数） | `text_delta` | ✅ 已是流式，且一条流跨**一次输入**（run 级，`agent_start`→`agent_end`） |

两家都已是**有摞有页的纯流式**。粒度差异（谁切得快）不影响结构。

## 接入形态（真正的来源分类）

产品名会变、会新增，**形态不会**。判定按形态走——队列只有三个入口，
所有接入方最终都落到下面五种之一：

| 形态 | 长什么样 | 谁在用 | 身份 | 收尾 |
|---|---|---|---|---|
| **A. 长连接流式** | 接入方自己开一条连接，边生成边发增量 | pi 扩展 | 接入方**自报** turn；页由翻页信号给（pi 发 `{page}` 帧） | 连接内 `{end}` / EOF，可靠；另有 `{cancel}` 自取消 |
| **B. hook 增量分批** | 工具渲染时按行批触发 hook，每批带增量 | Claude Code（MessageDisplay） | 每批 payload 里带 `turn_id` + `message_id`（缺失时回落）；Stop 只有 `session_id`，靠 `lastturn/` 反查 | 外部 Stop 钩子（**可能丢**），丢了靠宽限兜底 |
| **C. hook 终了一次** | 工具结束时触发 hook，payload 带完整回复 | 暂无接入方；**任何能配 stop hook 且 payload 有 `last_assistant_message` 的工具**都能接 | 拿 payload 里的 turn 号当摞号，没有就回落 `session_id` 反查；**一摞一页、不带 `--page`**——与 `ivox speak` 同形 | Stop 即完整，无缺口 |
| **D. 一次性 speak** | 命令行丢一段文本进来 | `ivox speak`（人工、脚本） | 无 | 发完即完整 |
| **E. 插队播报** | 用户主动开口，要立刻响 | Opt+Z 划词译文 | 无 | 发完即完整；**不进队列**，主节点暂停 + 独立节点念完接着播 |

**D 是陌生人，不插队。** 哪怕是用户自己在终端敲的，纸进了队列也没有名牌，
没人说得清它是哪一摞的后半截——老老实实排队。要插队必须显式 `--now`，
那是形态 E 从命令行走的一扇门，不是陌生人忽然有了特权。

两条**不进队列**的路，别混进上面这张表：

| | 做什么 | 与队列的关系 |
|---|---|---|
| **麦克风**（按住右⌘ / 右⌃） | 录音 → 语音转文字 → 文字落到光标所在的输入框 | **只调 `cancelAll(.speech)`**。用户的讲话是给 AI 的，不是让播报员复述一遍——所以一个字都不往队列递。全项目没有任何以 `speech` 入队的调用点，这是结构事实，不是约定 |
| **微信** | `sendMessage` / `sendTyping` / 长轮询 `pollLoop` | 只发消息和「正在输入」，**不发声**。聊天窗口里已经有文字了，再念一遍是打扰（[目的层](purpose.md) 早已裁定） |

**形态 C 是一整个类别。** 任何工具只要能配一个 stop hook、payload 里带
`last_assistant_message`，就能以「整段一次」的方式接进来——这是最低门槛的接法。
目前没有接入方占着，留着这条是因为它划的是「接得进」的下限，不是某个具体产品。

## 打断粒度：不归本文管

三档按键在任何来源下**行为一致**——因为摞号页号都是助理自编的，缺的从来不是编号。
**「这一摞里装着几页」这个事实由本文回答；按键的手劲属需求层**（见
[requirements.md 的三档一节](requirements.md)）。

⚠️ 本节早先写的是「拿得到摞号才能掀摞、拿得到页号才能掀页，都没有就只剩全掀」——
那是 2026-10-18 改判前的旧规矩，与代码相反，已删除。旧规矩作废的理由记在
[requirements.md](requirements.md) 的「能力边界」与 `purpose.md` 的裁决记录里。

## 准入标准（以后接新 agent 按这条判）

必须回答三问，答不出就在实现里退化成「无摞无页号」那一行（不是不接，是打断粒度退化）：

1. **摞从哪来** —— 拿不得到稳定的轮次标识？拿不到 → 无摞
2. **页号从哪来** —— 有没有「一条 assistant 消息」的边界（message id / item id / 显式翻页信号）？拿不到 → 页号为空
3. **怎么算说完** —— 有没有可靠的结束信号？没有就得靠兜底猜

前两问决定打断粒度；第三问决定要不要兜底机制。

## 链路事实：Claude 的身份是 hook 端造的

最容易误解的一处，**队列侧压根不知道 session 是什么**：

```
hook.sh 收到一批 MessageDisplay
  → 把这一批的 turn_id 写进 ~/.config/ivox/lastturn/<session_id>（每批覆写）
Stop 钩子到来（payload 只有 session_id + last_assistant_message，没有 turn_id）
  → 读 session_id，反查 lastturn/<sid>，取出摞号
  → 通过 --group 传给队列
```

- `turn_id` 缺失时回落 `message_id`；两者都缺才不带 group，退回普通播报。
- `lastturn/` 按 session 分文件存，为了两个会话并行时互不覆盖。
- **七天后自动淘汰**：这张表只为 Stop 反查而存在，回复结束就没用了。此前只涨不清（实测堆到
  30 个文件）；现在每轮 Stop 顺手扫一遍、删掉 mtime 超过 7 天的——一轮一次，一天几十次，
  代价可忽略。七天内可能还会被反查，更早的会话不可能还在对话里。
- ⚠️ **时序假设**：Stop 反查它，隐含假设「Stop 到来时它仍属于本 session 正在进行的这一摞」。正常交互成立；**用户中断 Claude 提前触发 Stop、紧接着又发起新回复**时可能错位。风险点在 hook 端，不在队列。

## 维护约束

- 接入方的能力边界（能不能拿到身份、有没有增量）是**对方工具的事实**，不是本项目的设计选择。判断依据一律回对方源码/文档查，别凭印象。
- 改接入方接线（hook 配了哪些事件、传了什么号）**必须同步改本文**，并回头看 playback-requirements.md 的场景清单还成不成立。
- 文档里每条「现状」都应能在代码或对方源码里指出出处；写不出出处的，标成待核实。
