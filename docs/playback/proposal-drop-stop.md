# 提案：拆掉 Stop 收尾信号

> **这是提案，不是现状。** 现状是 Stop 通路完整保留着；本文只把「拆掉它」这件事摊开，
> 等飞哥有空时裁决。未裁决前代码不动。
>
> 写于「收尾不再立墓碑」那次修复之后。

## 一句话

Stop 钩子现在只剩「让字幕早收 8 秒」这点作用，拆掉它对功能零影响——代价只是字幕晚 8 秒收起。

---

## 1. 现在的 Stop 是什么

Stop 是 Claude Code 的一个钩子事件：助手这一轮说完了，它通知 iVox「说完了」。

它到 iVox 后的完整接线：

```
hook.sh end 分支  →  ivox speak --final  →  socket 帧 {end:1}
   →  ConnectionHandler  →  queue.finishTurn(turn)  →  session.sealTurn(turn)
```

`sealTurn` 做两件事：**盖印**（这摞说完了，不会再有内容）+ **通知**（可以收字幕了）。

**2026-10-21 之前它还多干一件**：顺手立墓碑。那次修复（`7c34340`）把这件事拿掉了——
理由是「我说完了」这句话和正文走两条独立的路，谁先到没保证，实测有一次 Stop 早到 9 毫秒，
就把随后到达的最后一段 140 字静默丢弃了（用户听到的是「念到一半没了声音」）。

所以**现在**的 Stop 只管收字幕，内容生死它说了不算。

## 2. 为什么想拆它

- **它已经不是判决，只是提速**——「提前 8 秒收字幕」这点价值，配不配得上多一条通路，值得掂量。
- **它是抢跑的唯一来源**——刚才那次丢播报就是它惹的。机制拆了，这类事故的根就没了
  （而不是靠「这次没抢到」）。
- **删代码比加判据便宜**——拆掉是纯删除（下面第 4 节列了接线点），不用新增任何机制。

## 3. 拆了靠谁收尾

靠**空闲宽限**——这套机制本来就在跑：

> 队列见底、又还有没收尾的摞时，**先等设备把已排队的音频播完**（声音真停下才开始数，
> 否则会在尾音还没念完时判完、把字幕收掉），再静候 8 秒没新内容 → 判定「说完了」→ 盖印 + 收字幕。

也就是说：**功能不减，只是收尾晚 8 秒。**

（pi 那条路不受影响：pi 的 `{end}` 走流式帧，同一连接内按帧序到达，不会抢跑，
而且它本来就不经过 `end:1` 这条线。）

## 4. 要改哪几处

接线点已经摸清，纯删除，没有新增：

| # | 地方 | 删什么 |
|---|---|---|
| 1 | `scripts/hook.sh` | `end` 分支（约 40 行，含 `lastturn/` 那套 session→摞 的反查与清理） |
| 2 | `Sources/iVox/Commands/SpeakCommand.swift` | `--final` 参数与 `end:1` 帧的拼装 |
| 3 | `Sources/iVox/Network/ConnectionHandler.swift` | `end:1` 分支（`isFinal` 的两处处理） |
| 4 | `Sources/iVox/Playback/PlaybackQueue.swift` | `finishTurn()`（`sealTurn` 若无人调用则一并删） |
| 5 | `scripts/install-hooks.sh` | 摘掉 Claude Code settings.json 里的 **Stop 钩子注册**（另有 `~/.config/ivox/lastturn/` 目录可一并删） |

连带可清掉的：不再需要的 `lastturn/` 目录及其写盘逻辑（它只为 Stop 的反查而存在）。

## 5. 代价与风险

**代价**（都很小）：

- 字幕晚 8 秒收起
- 容器晚 8 秒清（念完的摞要等盖印后才被回收）
- `/health` 报的「发声点」在收尾后 8 秒内可能偏旧

**风险**：

- 空闲宽限**判「说完了」是按时间猜的**，不是按事实。模型跑工具时也是没动静的——
  工具跑 30 秒，队列空 8 秒就会判「说完了」。**内容不受影响**（队列里本来就没东西，
  后续新页到达照样揭印继续播），只是字幕会提前收一次，工具返回后内容又冒出来时字幕要重新弹。
  **字幕默认是关的**（`playback.captions = false`），只有开了字幕的用户才看得见这个闪。
- Stop 现在是「字幕立刻回」的保证。拆掉后若嫌字幕收得慢，把空闲宽限调小即可（8 秒是飞哥定的手感）。

## 6. 怎么验证

1. `make test`——现有 182 条必须全绿（本提案不新增测试，因为是纯删除）
2. `make check-tts`——21 条全绿（跑前要落静音闸 `touch /tmp/ivox-hook-muted`）
3. 手动一轮：说一句有内容的话 → 等它念完 → 确认 **8 秒后**字幕自己收起、队列清空、
   `/health` 的 `queued` 归零
4. 手动一轮：说一句**带工具调用**的话（中间有几十秒空档）→ 确认内容一句不落

## 7. 待裁决的点

1. **字幕晚 8 秒收，你接受吗？**（字幕默认关着，多半无感）
2. **工具调用期间字幕会闪一下**（只影响开了字幕的人），接受吗？
3. 要不要**和「取消摞、只留页排序」那次重构合并做**？
   - 合并：一次改完，但动的地方叠在一起，出问题难定位
   - 分开：先拆 Stop（小、纯删除、可快速验证），再动摞（大重构）
   - **建议分开**：两件事的风险量级差一个数量级，合并会让小的那个也背上大的验证成本

## 附：与「取消摞」重构的关系

「取消摞、队列里全是页」是另一件事（内部概念从三层降到两层、四条入队路径并一条、
`ConnectionHandler` 的「外部 group ↔ 助理摞号」对照表整个消失）。

**两件事没有依赖关系**：拆 Stop 不需要取消摞；取消摞也不需要拆 Stop。
但如果最终两件都做，Stop 拆不拆就无所谓了——因为那时收尾判据会重新设计一遍。
