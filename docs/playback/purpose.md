# 播报目的层

> **取舍听它的。** 它回答：**播报为什么存在，以及遇到取舍时听谁的。**
> 机制看不懂先翻 [paper.md](paper.md)（比喻层），它建立直觉但不裁决。
> 它不描述系统，只裁决。其余三层遇到争议翻上来：
> [接入方层](sources.md)（谁在说话）·
> [需求层](requirements.md)（必须做到什么）·
> [实现层](queue.md)（怎么做到）。
>
> 每条原则下面都记着**它裁决过什么**——只有裁决记录的原则才算数，光是好听的口号一律不作数。

## 一、即时反馈优先

**用户在等 AI 的时候，默认要有声音。** 宁可少说，不可无声。

- **裁决过**：「页要不要等整页写完再出声」——否。分层流式，宁可让页多一个「还在来」的状态，
  也不能让用户在等的时候干听。实测 Claude 每 0.1～0.5 秒就来一行，整页等完能等十几秒。
  ⚠️ **2026-11-02 部分改判**：新模型下**一页就是一条 assistant 消息**，
  接入方攒完整页才交（Claude 的 hook 攒到 `final=True`、pi 在 `message_end`），
  「等整页」这件事本身变成了「等这一条消息说完」——这是接入方的边界，不是队列的。
  队列这一侧不再有「页占位、正文陆续往里塞」这种形态。
- **裁决过**：「统一各个接入方的交付时机」——统一的是**结构**（页 → 句），
  不是**时机**。时机统一就会牺牲即时出声，不值。

## 二、打断权只归用户

**动手的只有人。机器最多借道，借完就走。**

- **裁决过**：新回复到达时要不要打断在播——否。改成按到达序排队、播全播完。
  理由不是礼貌，是实测：一次 868 字长回复被 199ms 后到达的 84 字短回复整条掐掉。
- **裁决过（2026-10-26 改判）**：Opt+Z 译文要不要清场——否，只临时插队，念完原顺序恢复。
  **改判后的形态：译文压根不进队列**——早先是「掐断在播的那一句 + 译文段插到队首」，
  代价是①正在念的后半截被掐掉且不重播；②队列里多出一摞没人认领的纸
  （容器为此专门开了一条「加急段」列表 + 第二套游标，两套并存迟早漂移）。
  现在主节点**只暂停**（缓冲原样留着，与右⌘说话一个语义），译文从**独立播放节点**出声，
  念完从原处接着播。**队列顺序一点没变、其余内容一个不丢，容器也回到只有一层。**
  判据：**要「当场就响」不等于要「进队伍排最前」**——后者只是前者的一个笨办法，
  顺带把队列搞成两层。
- **裁决过**：hook 的「提交即打断」分支——删。打断只由快捷键承担。
- **裁决过（2026-10-17，18:52 翻车之后）**：**「用户正在听哪一页」只能由设备已出声的位置
  回答，绝不由合成/排队进度回答。** 用户按了掀页，他动手的结果就必须由他决定；
  名义上打断权在他手里、实际不在，名存实亡。当时的起点取自合成进度，那东西领先真实发声
  2~4 秒，于是掀掉的是队列里下一个还没出声的页——正是他刚说过不要的那页。
  配套裁决：`dataConsumed` 领先真实发声 10~21ms **接受**，误差方向是安全的
  （指向正在响的，不指向还没响的）；要对齐得挂 `AVAudioEngine` tap，新增 IO 抖动风险，
  与收益不成比例。
- **裁决过（2026-11-02）**：**打断只有两档**：掀页（丢正在听的那一页）与全掀（清空队列）。
  原来的第三档「掀摞」随「摞」这个概念一起消失——它要回答「这一摞是哪些页」，
  而新模型里**页之间不再有归属关系**（队列是页的 FIFO，先来先进）。
  **判据：一档打断若需要维护一个「哪些页属于谁」的关系，它就在给队列加第二维度。**
  「不要这一页」与「都不要了」已经覆盖了用户能表达的两种意图；
  再加一档，只会让「用户以为掀的是一堆、实际掀的是一层」的事故多一种。

## 三、不凑合

**要么做对，要么不做。半成品比不改更糟。**

- **裁决过（2026-11-02，本次最大的一次整改）**：**队列里只留「页」一层，摞整套拿掉。**
  早先的模型是「段（摞）→ 页 → 块」三层容器，配一整套配套机制：
  外部 `turn_id` ↔ 自编摞号的对照表（挂在跑腿侧）、墓碑（`deadTurns`）、
  「已封 / 未封」的收尾记账、空闲宽限、Stop 收尾信号、`finishedTurns` 终判表。
  这些机制**每一件都只在「页属于某一摞」这个前提下才有意义**，而那个前提本身
  是历史包袱：早先因为外部编号不可靠，助理不得不自编号并做映射表，
  映射表一多，「外部号 ↔ 自编号」两套身份就开始打架（实测按一次键掀掉 34 句，
  其中只有 6 句是新回复）。
  **判据：一个概念若要求整套配套机制才能成立，就该先问它该不该存在，
  而不是给它加判据。** 拿掉「摞」之后：一摞纸的来路不再需要归拢、
  不再需要墓碑拦增量、不再需要等端说「我说完了」、不再需要兜底宽限，
  队列**排空即收尾**——整套机制跟着消失，容器只剩两层（页 → 句）。
- **裁决过**：「先加游标、容器留在队列里，之后再搬」——否。分步的每一版都是
  「队列仍然认摞」的将就形态，最后两套并存谁也不敢删。
- **裁决过（2026-10-17）**：「播完了但容器里还留着」这个将就形态——不留。
  容器原先只增不减，听完的摞一直占着位置，于是 ① 对外报告的「正在听哪摞」在播完之后还在撒谎；
  ② 更要命——播完后用户随手按 Ctrl+2，起点落在那个早已播完的摞上、给它立了墓碑，
  而 Claude 那一摞往往**还在继续送页**（一次输入 = 好几页），墓碑一立，后续页全被静默丢弃。
  现在每次泵顺手回收「一句都不剩」的页（判据是发声点，不是排队进度），收尾那条
  已确认真静音的路径连正在响的最后一句也一起清。
- **裁决过（2026-10-19）**：「MLX 崩了是 iVox 的 bug，所以修 iVox」——**修不了就隔离**。
  Metal 命令编码器析构时重复释放 GPU 命令队列直接 SIGTRAP，上游（mlx-audio-swift /
  mlx-swift）本地即最新、无新提交，encoder 又由 `generateStream` 内部创建、Swift 侧拿不到引用，
  **无从拦截**。同一个病根此前已经露过两次脸（取消时 commit 未收口、copy_gpu SIGSEGV），
  每次都打了个补丁在**特定路径**上苟住，第三次照旧炸——说明「在会炸的东西上打补丁」这条路本身
  就不成立。所以把 MLX 整个搬进子进程（誊清员），主进程不碰它、也不因它崩。
  **判据：一个依赖崩了且修不动，不等于本项目要跟着它一起崩；把它圈出去，比给它加判据更划算。
  隔离顺带买到「谁没干好一眼可见」——崩在哪个进程，日志就落在哪个文件。**
- **裁决过（2026-10-18，历史）**：「无编号内容并进同一段」这个图省事的合并——**段就是摞**，
  无编号的稿一份单独开一段。原实现把没 turn_id 的稿子全塞进队尾那个无编号段，于是
  **不同时间的多次回复被焊成一摞**：掀摞的契约是「掀掉你此刻在听的这一摞，
  从下一摞接着播」，焊成一摞后「下一摞」根本不存在，按一次等于全掀
  （18:11 实测：掀掉 34 句，其中只有 6 句是新回复，其余 28 句是上一条长回复的余量）。
  **理由**：turn_id 只是摞的**编号**，不是摞**存在**的前提。
  ⚠️ **2026-11-02 作废**：摞这个概念已整套拿掉，问题不再以「摞」的形式出现；
  但那条结论仍然成立——**身份是容器自己的事，不由外部决定。**

## 四、服务不了目的的结构不进术语

**一个说法若只说得清「代码里是什么」、说不清「为了什么」，它就是歧义的温床。**

- **裁决过（2026-11-02）**：**播报只剩两个词：页、句。**
  「摞」是历史概念，作废（见上「不凑合」那条裁决）。
  「句」是**合成单位**（≤80 字），纯实现细节、用户不感知——但它必须是**一个词**，
  不能一会儿叫「块」一会儿叫「条」一会儿叫「分段」。
  **判据：用户不感知的东西不该占用户认知，但代码内部仍要给它一个唯一的名字**，
  否则同一个东西在日志、注释、文档里有三种叫法，查问题时会以为它们是三样东西。
- **裁决过**：「桶」曾是第四个术语——它是队列的排队单位，用户从不按它操作。
  拿实现语言描述语义，「一摞 = 一桶」于是自相矛盾。降级为实现词。
- **裁决过**：动词集曾经有「读下一页 / 跳整摞 / 掀桌 / 撕 / 翻 / 丢弃 / 清场」七套说法——
  同一套动作混比喻和实词。收成「掐」「掀」两个。
- **裁决过**：「身份强弱分三档」这类只描述实现的说法——按用户能做什么来分
  （能不能掀页、能不能全掀）。
- **裁决过（2026-10-17）**：用户措辞里的**「当前」**——删。三档打断改说成
  「我不想听这页了，听下一页 / 都不听了」。
  理由：说「掀当前那一摞」就等于要求代码维护一个「当前是谁」的状态，而那个状态正是
  这次翻车的载体；改说「听下一页」之后，起点只需回答「用户耳朵里那页是谁」，
  这个问题有唯一真源，不与合成进度纠缠。**判据：一个词如果逼着代码去维护一个
  实现层的陈旧状态，它就不该出现在用户话里。**
- **裁决过（2026-10-17）**：一个概念不兼职两职。旧代码里「游标」既是**队列进度**
  （已排进播放器）又是**用户感知位置**（用户耳朵里那页），两者相差 2~4 秒却共用一个数，
  这正是病灶。现在拆成两个数：`cursorSeq`（队列进度，消费层用）与
  `audibleSeq`（发声点，干预层用）。**判据：凡两个数需要把一个同步成另一个，
  就是两套并存，必须删一个。**
- **裁决过（2026-11-02）**：**「说完了」这个信号不进术语。**
  早先有两套收尾判据（端的 Stop 钩子 + 空闲宽限兜底），它们服务的是「摞」——
  只有知道「这一摞还有没有下文」才需要问端。页的 FIFO 没有这个问题：
  **桌上没纸、声音也停了，就是说完了。**
  判据：**一个判据若只为一个已删的概念服务，就跟着它一起删。**

## 五、不打扰

**播报是配角，主角是用户和 AI 的对话。**

- ~~**裁决过**：播报借还背景音乐——整条删除。借了还、还了借的抖动就是这么来的
  （Claude 分批送来，批间停顿一超时就误判「说完了」还音乐，下一批到又借走）。
  音乐只归语音输入——只有它真需要麦克风安静。~~ **2026-10-21 部分改判**：
  **借还（pause/resume）仍然不回来**——抖动就出在状态来回切上。
  但「播报时把汽水音乐压到背景音量」回来了，**因为它不是借还、是改数值**：
  播报开始降 5 格、播完升 5 格（`SodaVolumeDucker`），播放状态压根没动，抖不起来。
  已知取舍：那 20 格是汽水音乐的**应用内**音量、本机读不到 → 只能相对调节，
  音量本来就低时会触底、播完升回去不等于原值。
  判据补一句：**让路优先选「改数值」而不是「改状态」**——状态切换会抖，数值不会。
  ⚠️ 2026-10-25 改判「什么时候让、什么时候还」：**判据归浮窗服务**（`OverlayService`）——
  **只跟浮层走**：浮窗在屏上就让路，**浮窗一消失立刻恢复**（不再等「播报结束」那一刻，
  字幕收了、译文还在屏上时不该把音乐放回来）。
  「iVox 正在出声」这半个判据被否了：让路与否只看**屏幕上有没有东西占着**，
  声音归声音、屏幕归屏幕（字幕关掉时，播报也不该压着音乐）。按下去的动作仍是 `SodaVolumeDucker`。
- **裁决过**：字幕要不要强制——不要，配置可关。
- **裁决过**：微信链路要不要出声——默认**不**。聊天窗口里已经有文字了，再念一遍是打扰。
  2026-10-26 补：做成开关 `[wechat] speak`，默认 `false`（不念），改成 `true` 才念。
  裁决的默认值没变，只是不再「焊死」——微信侧的 claude 照样会触发 Claude Code 那套
  hook（hook 配在 user 级 settings.json，谁启动 claude 都吃），所以「不念」这条得由
  daemon 按来源明确裁决，不能靠「碰巧没出声」。

## 六、诚实标注边界

**做不到的事写清楚做不到，不假装能。**

- ~~**裁决过**：「掀页」在文档里怎么写——写明它**掀不彻底**：页号每批才送来，
  还没来的页拦不住。~~ **2026-10-18 作废**：页号改由助理自编，事先就有，
  掀页掀得干净，各档在所有输入形态下都成立。
- **裁决过（2026-11-02）**：**没有「还没来的页」这回事了**——接入方一次交一整页，
  页不是分批来的。「这一页之后还有没有下一页」是事实而非缺陷：
  没写完的东西拦不住，但用户要放弃的粒度就是**一页**，那正好是队列的单位。
- **裁决过**：自检腐烂（2026-10-16 三个用例假绿、2026-10-17 两条因日志门限假红）——
  发现即记，记的是**为什么**不是「改好了」。

## 这一层怎么用

三层里出现分歧时，顺序是：

1. **先问目的是什么**（本文）——目的是否被满足
2. 目的满足不了再看是不是需求层写错了（requirements.md）
3. 再看是不是实现层能解（queue.md）

**倒过来做**——先想着怎么改代码、再倒推目的——就是凑合。本文的作用就是拦住这件事。

## 维护约束

- 新增原则必须附**裁决记录**（它裁决过什么）。没有裁决记录的原则说明还没被检验过，
  写在这里只是愿望。
- 原则之间冲突时，以本文为准；发现冲突就改本文，别让两层各执一词。
